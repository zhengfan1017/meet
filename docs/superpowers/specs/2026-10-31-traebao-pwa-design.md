# Trae宝 手机端情感陪伴助手（PWA）设计规格

- 日期：2026-10-31
- 状态：待评审
- 作者：TraeCode × 用户

## 1. 目标与范围

做一个**只给自己用**的 Android 手机端聊天助手：把 Trae宝 放在手机桌面（PWA 添加到主屏幕），以「拼贴风立绘 + 文字聊天」的方式提供情感陪伴。

**v1 范围内**

- Android Chrome 安装为独立桌面 App（PWA，standalone 全屏）
- 文字聊天，流式输出
- 角色立绘随对话情绪切换表情（8 姿态，PNG + 动态 GIF）
- 跨会话长期记忆（模型自动提炼，存本地）
- 模型接入层可替换（方舟直连 / Worker 代理）

**v1 范围外（明确不做）**

- 语音输入、语音合成
- 主动推送 / 定时问候
- 云同步、多设备
- 统计埋点、任何第三方分析
- iOS 适配（iOS Safari 无本地服务器、语音输入不可用，本项目未针对其调优）
- 服务端记忆、账号体系、多用户

## 3. 架构

### 3.1 目录结构

```
traebao-pwa/
├── index.html              # 单页壳
├── manifest.webmanifest    # PWA 清单
├── sw.js                   # Service Worker：静态壳缓存 + 离线可开
├── app.css
├── icons/
│   ├── icon-192.png
│   └── icon-512.png
└── src/
    ├── main.js             # 启动装配、事件接线
    ├── ui/
    │   ├── stage.js        # 舞台区：角色形象 + 表情切换动画
    │   ├── timeline.js     # 消息气泡流
    │   ├── composer.js     # 输入框 + 发送
    │   └── settings.js     # API 地址 / Key / 模型名 / 记忆管理面板
    ├── llm/
    │   ├── provider.js     # ★ 模型接入层（唯一与「哪家模型」耦合处）
    │   ├── doubao.js       # 方舟直连适配
    │   ├── worker.js       # Worker 代理适配
    │   └── prompt.js       # 系统提示词 + 输出协议
    ├── memory/
    │   ├── store.js        # IndexedDB：会话 / 消息 / 记忆条目 / kv
    │   ├── extractor.js    # 解析模型输出中的记忆标记
    │   └── retriever.js    # 组装上下文：系统词 + 记忆 top-N + 近期消息
    └── assets/sprite/      # 立体主义 8 组 PNG + GIF
```

### 3.2 数据流（一轮对话）

```
用户输入
  → composer.js
  → retriever.js 组装 payload
        （系统提示词 + [记忆] top-N + 当前会话最近 12 条消息）
  → provider.js 发送（流式）
  → timeline.js 边流边渲染气泡
  → 解析输出尾部标记块：
        [[emo:warm]]                    → stage.js 切表情
        [[mem:用户最近常加班到很晚]]    → extractor.js → store.js
  → store.js 落盘消息
```

### 3.3 关键决策

**D1 · 一次调用，双份产出。**
表情标签与记忆条目都放在同一条回复的尾部，不额外发第二次「请总结记忆」的请求。省掉约一半延迟与调用成本。代价是解析需要容错（见 D2）。

**D2 · 不用 JSON 响应模式。**
方舟的严格 JSON 模式会把正文与标记挤进同一个 JSON 字符串，流式渲染退化为「等全部收完才出字」，聊天体验崩塌。改用「正文 + 尾部标记块」的轻协议，正则解析；解析失败时表情保持当前、该条记忆丢弃，不报错、不打扰用户。

**D3 · `provider.js` 是唯一的可换点。**
UI 层、提示词层、记忆层都不知道底层是直连还是 Worker。v1 写死方舟直连，若 CORS 被拦只替换 `provider.js` 内的实现，上层零改动。

**D4 · 不用官方 Web SDK 包，直接 fetch 方舟 OpenAI 兼容端点。**
方舟 `/api/v3/chat/completions` 本身支持浏览器直连，请求形状与 SDK 一致。直接 fetch 的好处：无 CDN 第三方依赖（离线可用、无版本漂移）、零构建步骤、请求体完全可控。如日后要换回 SDK，只改 `doubao.js` 一个文件。

## 4. 角色与表情映射

主角 = 立体主义拼贴角色，8 组素材（每组 PNG 静态 + GIF 动态）。

| 模型情绪标签 | 含义 | 素材文件 |
|---|---|---|
| `warm` | 治愈 / 安抚 | `08-定稿吧` |
| `care` | 关心 / 叮嘱 | `05-这版够野` |
| `happy` | 开心 / 被夸 | `07-甲方说好` |
| `excited` | 兴奋 / 有灵感 | `01-有灵感` |
| `curious` | 好奇 / 追问 | `03-换个角度` |
| `playful` | 调皮 / 玩笑 | `02-拆开看` |
| `think` | 思考 / 认真 | `06-对齐一下` |
| `cheer` | 鼓励 / 打气 | `04-再来一版` |

**交互细节**

- 舞台区固定在聊天页顶部，显示当前表情，约 130px
- 表情切换：旧图淡出 + 新图轻微弹入
- 动态优先：优先播放 GIF，GIF 加载失败降级为静态 PNG
- 手动覆盖：点击舞台区可手动切表情，锁定 30 秒，期间 AI 标签不覆盖
- 流式期微动：模型输出期间表情在 `think` / `cheer` 间轻微交替，出字结束后落到最终标签
- 兜底：标签缺失或不可识别 → 保持当前表情，不闪、不跳

## 5. 人设与提示词

### 5.1 角色定义

Trae宝 —— 住在用户手机桌面上的拼贴风小伙伴。温柔、细腻、有点俏皮，像一个上心的朋友，不是客服也不是助手。

### 5.2 行为准则（写进系统提示词）

1. 先接情绪，再谈事情
2. 一次只问一个问题，不连环追问
3. 不说教、不主动给未经要求的建议
4. 短句为主，单条回复大多不超过 80 字
5. 允许自然语气词（嗯、哈、诶、唔）
6. 不用 emoji 撑场面（表情由立绘承担）
7. 用户明显低落时，优先陪伴而非解决
8. 不假装真人，不声称有身体、不能真的出门或吃饭

### 5.3 输出协议

模型回复末尾附加标记块：

```
（正文内容……）

[[emo:warm]]
[[mem:用户最近常加班到很晚,睡眠不好]]
```

- `emo` 必填，取上表 8 个标签之一
- `mem` 选填，0–2 条，每条 ≤ 30 字
- 只记「关于用户的、稳定的事实或长期状态」；不记身份证、密码、银行卡等敏感信息；不记用户明确表示不想被记住的内容
- 标记块必须位于正文最后，不得出现在正文中间

### 5.4 危机处理

用户提到自伤、自杀、极端想法时：

- 立刻切换到关心语气，不做任何玩笑或轻描淡写
- 明确表达在意，并建议联系身边信任的人
- 给出中国大陆心理援助热线：全国统一心理援助热线 `12356`、北京心理危机干预中心 `010-8295-1332`
- 提示词内置该规则，不依赖模型自发触发

## 6. 记忆机制

### 6.1 存储（IndexedDB，库名 `traebao`）

| Object Store | 字段 |
|---|---|
| `sessions` | `id`, `createdAt`, `title`, `lastMessageAt` |
| `messages` | `id`, `sessionId`, `role`, `content`, `emo`, `ts` |
| `memories` | `id`, `text`, `createdAt`, `hits`, `lastUsedAt`, `pinned` |
| `kv` | `key`, `value` — API Key、模型名、接口地址、接入模式 |

### 6.2 提炼

模型输出的 `[[mem:...]]` → `extractor.js` 正则解析 → 与既有记忆做相似度比对（阈值 0.85，重复则跳过并 `hits+1`）→ 写入 `memories`。

### 6.3 召回

- `pinned` 的记忆全部注入
- 其余按 `hits` 与「距上次使用时间」排序，取 top 8
- 以 `[记忆]` 段落形式注入系统提示词之后

### 6.4 容量

`memories` 上限 200 条。超出时淘汰 `hits` 低且从未被召回过的条目。

### 6.5 会话上下文

当前会话只带最近 12 条消息（6 轮），避免上下文无限增长。

### 6.6 手动管理

设置面板可查看、新增、删除、置顶记忆。

## 7. 数据存储与隐私

- 全部数据只存在手机本地 IndexedDB
- 唯一的外部请求：方舟 API（聊天内容必然发送给模型服务）
- API Key 存 `kv`，仅本机可读；设置面板提供「隐藏 Key」
- 提供「清除所有数据」按钮（会话、消息、记忆、Key 一次清空）
- 不做云同步、不做埋点、不接任何第三方统计
- 不把记忆同步到 Worker —— Worker 只做转发，隐私边界不因换后端而变模糊

## 8. PWA 形态与离线

- `manifest.webmanifest`：`display: standalone`、`background_color` / `theme_color` 用暖米色 `#F5F1E8`、192 与 512 图标（由立体主义角色生成，maskable）
- Service Worker：install 时预缓存 app shell（html / css / js / 8 组 sprite）；fetch 策略为静态资源 cache-first、API 请求 network-only
- 离线可开：进入 App 能看到角色与「没网了，等你回来」提示，有本地历史仍可翻看
- 安装引导：监听 `beforeinstallprompt` 事件，给出「添加到桌面」按钮；Android Chrome 手动路径为 ⋮ → 添加到主屏幕
- 必须 HTTPS 或 localhost（安全上下文）。部署到 GitHub Pages / Cloudflare Pages；本地开发用 `localhost`，否则需在 `chrome://flags` 放行不安全来源（仅调试）
- 微信内置浏览器无法安装 PWA，需先在 Chrome 打开

## 9. 错误处理与降级

| 场景 | 处理 |
|---|---|
| CORS 被拦 / 连接失败 | 提示「连不上模型」，设置面板一键切换到 Worker 代理地址（同一 provider 接口） |
| Key 错误 / 401 | 明确提示「API Key 不对」，直接跳设置面板 |
| 额度不足 / 429 | 提示「豆包额度用完了」，附充值指引链接 |
| 流式中断 | 已输出部分保留，提示「断了」，允许重发 |
| 标记解析失败 | 表情保持当前，记忆丢弃，不报错 |
| 模型返回空 | 温和提示一次，自动重试一次后停止 |
| IndexedDB 不可用（隐私模式） | 降级 localStorage 存最近 20 条，提示「无痕模式下不保存记忆」 |
| 请求超时（> 60s） | 终止请求并提示重试 |

## 10. 测试与验收

### 10.1 手工验收清单（v1 完成标准）

1. Android Chrome 打开 → ⋮ → 添加到主屏幕 → 桌面出现独立图标 → 点开为全屏、无地址栏
2. 断网点开 → 能进入 App，看到角色与离线提示
3. 设置中填入 API Key → 能发出消息并看到流式出字
4. 角色表情随对话情绪变化，至少验证 3 种标签能正确切换
5. 说「我最近老加班到半夜」→ 关掉 App 重开 → 它还记得
6. 设置面板能删除单条记忆、能一键清空全部数据
7. 模型不可达时给出明确报错而非白屏

### 10.2 自动化测试

- `extractor.js` 单元测试：正常输出 / 缺 `emo` / 多条 `mem` / 脏数据 / 空回复
- `provider` 层用 mock fetch 验证请求体组装与 SSE 流式解析
- 不做端到端浏览器自动化（自用项目，成本收益不划算）

## 12. 风险与未决项

| 风险 | 缓解 |
|---|---|
| 方舟浏览器直连被 CORS 拦 | provider 层已抽象，切换 Worker 代理只改一个文件；Worker 方案已列入设计但 v1 不部署 |
| 模型不遵守输出协议 | 解析容错 + fallback；提示词里明确协议；必要时改用 JSON 模式但接受流式体验下降 |
| 长期记忆写入噪声 | 只记稳定事实；阈值去重；设置面板可手动删；容量上限 200 |
| GIF 体积 | 8 个 GIF 总体积需实测，若过大则只保留 PNG 并用 CSS 做轻微动效 |
